## 0. 设计总纲

### 0.1 一句话定位

**"看得见"的电竞经理**——继承足球经理式的深度模拟骨架，把"看比赛"从文字流升级为可回放、可分享的战术直播，用事件驱动替代日历空转，让十年生涯成为一段可以晒出来的故事。

### 0.2 对原作调研结论的直接回应

| 原作痛点（调研 §8） | 本作对策 | 落点章节 |
|---|---|---|
| 比赛只有文字观战，无地图可视化 | 确定性模拟输出回合事件流 → 2D 战术回放器 + 转播级 UI | §5 |
| 空档期机械推进、"点按钮看报告" | 事件卡流 + 智能建议收件箱，决策密度前置 | §9 |
| 17 页弹窗引导 | 系统随进度解锁 + 首席助教提示（基于状态计算的前 3 建议行动） | §9.1 |
| 信息可视化贫乏（全文字表格） | 选手雷达图、状态曲线、战术板图示、赛后热图 | §10 |
| 单线程演算全世界，观战崩溃 | 模拟核心纯 TS + Web Worker，渲染与演算解耦，性能预算化 | §11 |
| 无分享/社交 | 赛季海报生成器 + 确定性对局回放链接 | §9.4 |
| 数据静态快照 | 数据源抽象层：虚构联盟生成器与真实数据接入共用一套 Schema | §4.4 |

### 0.3 三大设计支柱

1. **比赛剧场（Match Theater）**：每场比赛 = 一段可观看、可暂停、可分享的直播。模拟引擎必须输出结构化事件流，UI 是转播，不是报表。
2. **活的世界（Living World）**：AI 战队有性格、有叙事、有記忆。玩家的每个选择在世界里留下痕迹（宿敌、舆论、门下弟子）。
3. **生涯叙事（Career Arc）**：十年执教是一场有章节的故事。起点（次级联赛）、转折（国际赛）、结局（名人堂或黯然下课）都要有仪式感和可分享的产物。

### 0.4 明确不做的事（反范围）

- ❌ 不做选手实时操作/QTE——经理是脑，不是手
- ❌ v1 不做真实选手 IP——用虚构联盟规避法律风险，数据层预留真实数据接入（见 §4.4）
- ❌ 不做多人实时对战——只预留异步 PvP 联赛钩子（§11.5）
- ❌ 不做手游化抽卡/体力付费——买断 + 打赏，经营模拟玩家反感数值付费

## 1. 玩家幻想与受众

### 1.1 核心幻想

> "我是这支战队的教练和总经理。我不开枪，但每一次胜利都由我设计。"

玩家的三种时刻：
- **建筑师**：搭阵容、定战术、练新秀，看数据曲线成长
- **博弈者**：转会谈判、合同拉锯、赛前针对，赢在开打之前
- **叙事者**：见证弟子从 17 岁新秀成长为世界赛 MVP，把战队的故事讲给朋友听

### 1.2 目标受众（按优先级）

1. **核心**：FM/足球经理、Out of the Park 玩家 ∩ 战术射击（VALORANT/CS）观众，18-35 岁，能接受文字密度，追求系统深度
2. **次级**：电竞观众想"执教自己喜欢战队"的代入需求（v2 真实数据包的目标人群）
3. **外围**：轻模拟玩家，被"生成赛季海报/短视频式集锦"分享吸引进来

### 1.3 留存模型

- **次留**：开局 30 分钟内必须打完第一场"看得见"的比赛并赢下（脚本化保证第一场为优势局）
- **7留**：第一个转会窗口（Day 8-12 开启）+ 第一名青训新秀试训
- **月留**：第一个国际赛（Masters）出线争夺
- **长线**：五年之约分支 + 名人堂结局 + 赛季海报收集

## 2. 核心循环（三层嵌套）

```
微循环（每回合 = 赛季中 1 天 / 空档期 1 周）
├─ 查看收件箱：智能建议 Top3 + 事件卡（0~3 张）
├─ 花行动力：对外事务（报价/约战/商务/谈话）
├─ 免费操作：训练安排 / 战术预案 / 首发轮换
└─ 推进 → 世界演算 → 报告流（分级呈现，不打断；停靠规则见 §9.6）

中循环（每个赛段 ≈ 4~10 周）
├─ 赛段目标（董事会下达）→ 常规赛/杯赛 → 季后赛
├─ 每场比赛：赛前准备（情报/BP/预案）→ 观战 → 赛后（集锦/采访/海报）
├─ 转会窗开关、版本更新、疲劳与伤病管理
└─ 赛段结算：目标达成 → 信任/声望/资金结算

宏循环（赛季 → 生涯 10 年）
├─ 赛季：冠军积分 → 冠军赛资格 → 年度颁奖典礼 → 海报生成
├─ 休赛期：阵容重组、青训营、教练组升级、设施扩建
└─ 生涯：声望阶梯（次级→一级→豪门）→ 五年之约分支 → 名人堂结局
```

**节奏原则**（对原作最大的节奏修正）：**永远不让玩家连续推进超过 7 天而不做任何决策**。若系统检测到"连续 3 个空回合无事件无操作"，注入一张低风险事件卡（路人采访、粉丝来信、老将闲聊）维持世界活性。

## 3. 幻想落地：开局体验（First 30 Minutes 脚本）

| 时间 | 玩家在做什么 | 设计意图 |
|---|---|---|
| 0-3 min | 捏人：姓名/年龄滑杆 → 随机 3 选 1 出身 → 8 点天赋分配 | 继承原作（验证有效），但天赋页配"推荐配置"一键按钮 |
| 3-6 min | 选队：按声望列出愿意雇佣的俱乐部（次级队为主），每队展示：阵容概览雷达、薪资健康度、董事会期望风格 | 选队即选剧本：摆烂队/准豪门/重建队三种开局脚本 |
| 6-10 min | 交互式引导（非弹窗）：以任务清单形式走完"定首发→选英雄→排第一周训练" | 系统解锁制：此时转会/商务/财务均锁定 |
| 10-18 min | 推进 4 天 → 第一场联赛（**脚本优势局**）→ 强制进入观战模式 3 回合教学（暂停喊一次战术）→ 快进到结束 | 首战必看：让"比赛剧场"在第一次推进就兑现 |
| 18-30 min | 赛后：首张集锦海报生成（自动弹出分享按钮）→ 解锁训练页深度功能 → 第二场比赛自然留存点 | 分享钩子最早在第 20 分钟出现 |

## 4. 世界与内容结构

### 4.1 联盟架构（虚构，MVP 单赛区）

```
先锋冠军巡回赛 VCT-P（虚构名，待定）
├─ 一级联赛 VCT-P · 两赛区各 10 队（v0.5 起 4 赛区）
│    赛区 A「霞赛区」/ 赛区 B「岚赛区」
└─ 次级联赛 ACES 挑战者 · 每赛区 8 队（含 2 支玩家可选"废墟队"剧本）
```

- 每队：7 人名单（5 首发 + 2 替补）、主教练（三维）、助教/分析师 0-2 名、设施 0-95、预算
- 选手总数：v0.5 约 220 人（10+8 队 ×7 ×2 赛区）+ 自由市场 40 人 + 青训池
- AI 战队**性格标签**（本作新增，原作只有数值）：豪购型 / 青训型 / 稳守型 / 换血狂魔——决定其转会窗行为偏好，让世界可读可预测
- 性格同样接进比赛引擎（v1.9）：豪购型强起阈值降至 $1800 且强起概率 +20%、稳守型在关键回合主动使用暂停、青训型更愿意给新秀出场时间、换血型更早挂牌老将——场上体感与转会行为同源

### 4.3 版本系统（v1.1 修正：meta 二维化——英雄强度 × 地图适配）

- **二维评估模型**：英雄实力 = 全局 meta 系数 meta[agent] × 地图适配 fit[agent][map]（0.70–1.30，由技能组与地图几何的关系决定：侦察能力在开阔图增值、封闭图贬值；信息差英雄在小图更稀缺等）。fit 是世界常量（新图加入时更新），meta 是版本变量——**版本调整只动 meta，但强度结论必须两者相乘**。fit 的生成方法（v1.9）：**地图几何标签**（开阔度/点位数/垂直度/通道宽度）× **英雄机制标签**（侦察/烟幕/闪光/信息/机动）查表推导初始值，上线后用职业出场数据校准——与 §5.4 大招分级共用同一套标签基建，不做手工拍数
- **Patch 公告分两层**：全局定位（"黑梦整体削弱 −5%"）+ 地图级影响清单（"在『莲华古城』其控图价值仍高于猎枭——该图猎枭适配 0.85，平替不成立"）
- **平替推荐引擎**（修正原作式误荐）："A 被削了用谁顶"的推荐分 = fit[候选][本图] × meta[候选] × 职责覆盖匹配度（§6.1），三项加权缺一不可；推荐结果**按图给出**，不再有全局通用答案
- 版本公告页显示全联盟使用率变化 + **每张图的阵容 meta 榜**（当前版本各图前三阵容）
- 版本修正项**按图**进入比赛引擎（替换原全局 meta 修正），逼玩家每赛段重审预案——"活世界"的节拍器

### 4.4 数据源抽象层（关键架构决策）

```
┌──────────────────────────────┐
│   数据 Schema（统一）          │  ← 与调研导出的原作 Schema 同构
│   Team / Player / Agent /     │
│   Coach / MatchHistory        │
└──────────┬───────────────────┘
           │
   ┌───────┴────────┐
   │ Generator 后端 │           │ Ingest 后端（v2）
   │ 种子化虚构生成器 │           │ 真实数据抓取+分位映射
   │ （默认，合规）    │           │ （vlr/Liquipedia 风格管线）
   └────────────────┘           └──────────────┘
```

- **v1 用种子生成器**：输入随机种子 → 输出全套联盟（选手属性按位置分布模板生成，名字从虚构词库组合，AI 性格标签随机分配）。同一种子世界一致，便于测试与复盘
- Schema 与原作调研导出的 JSON 同构（`research/extracted/*.json` 就是模板），v2 若拿到数据授权/自行抓取，可无缝切换真实联赛包
- 生成器需保证：每位置至少模板分布合理（决斗者多输出属性）、全联盟 overall 正态分布 μ=70 σ=8、每队 1 名 IGL
- **英雄层沿用原作方案**（v1.1 确认）：英雄使用无畏契约本体本地化名称（幽影/猎枭/尚博勒…）与官方立绘头像，与原作一致；选手层 v1 用生成名 + 程序化头像，v2 接真实数据包时再切换真实选手名与照片管线

## 5. 比赛模拟引擎与可视化（支柱 1）

### 5.1 设计原则

1. **模拟与呈现分离**：引擎一次性输出整场事件流（JSON），播放器只负责渲染——观战崩溃问题从架构上消灭（原作是边算边渲染）
2. **确定性**：同一 seed + 同一输入 = 同一比赛。回放、分享链接、Bug 复现、未来异步 PvP 全部依赖此性质
3. **数值骨架继承原作**（已验证自洽），仅做可读性简化
4. **教学局例外**：开局首场使用固定 seed 与预设状态的脚本局（标记 scripted，不计生涯统计与成就）——脚本是预设输入而非模拟干预，与确定性原则不冲突

### 5.2 核心数值（继承 + 微调，全部公开可调）

**选手有效能力**
```
eff = overall × (1 + (form−70)×0.003 + (morale−70)×0.002 − fatigue×0.0015 − [带伤 0.20])
```

**每图团队强度**
```
base = Σ(首发 eff × [1.22, 1.10, 1.00, 0.90, 0.78]) / Σ权重      ← 明星倾斜
atk/def = base + Σ修正项
修正项（目标总量程 ±6，超出即失衡）：
  igl        (igl−60)×0.09，无 IGL = −4
  化学       ((teamwork+comm)/2 − 65)×0.07 + 队伍羁绊 ×0.04
  教练       (coach战术−60)×0.05 + 经理战术技能 ×0.06 − 1
  针对准备   情报值 ×2.2（侦察对手后有效）
  meta       阵容 vs 当前版本 meta 权重（§4.3），±2.5 封顶
  图池       (mapPref−50)×0.07
  熟悉度     英雄熟练度集合函数，0~2
  风格克制   五风格相性表，±1.8（见 §7.1；双方风格由阵容职责向量推断，见 §6.1）
  缺人       每少 1 人 −18
atk += 风格攻加成 + (avg aim−65)×0.05
def += 风格守加成 + (avg awareness−65)×0.05 + 1.5        ← 防守方固有优势
midRound = (clutch 均值−65)×0.05 + igl×0.06              ← 残局/追分
```

**回合胜负**
```
m = (攻 atk − 守 def) + buy 修正 + 暂停修正 + swing(σ=6，每图固定)
落后方：m += 0.35 × midRound（仅落后方获得，制造翻盘叙事）
P(攻胜) = 1 / (1 + exp(−m / 30))                          ← k=30
```

**经济**（原作数值直接继承，已验证手感）
```
手枪局 $800 强制 eco；≥3900 full；≥2200 时 55% force
战力修正：full 0 / force −6.5 / eco −15
胜 +3000；负 1900 + min(连败,2)×500；存活奖金 ±200/人；上限 9000
```

**角色系数**（写入引擎的分工）
```
击杀权重：决斗 1.08 / 自由 1.03 / 先锋 0.98 / 哨卫 0.96 / 控场 0.93
死亡权重：决斗 1.28 / 先锋 1.08 / 自由 1.00 / 控场 0.90 / 哨卫 0.88
首杀权重：决斗 2.0 / 先锋 1.3 / 自由 1.0 / 哨卫 0.6 / 控场 0.5
（v1.1）系数按英雄职责向量插值，不再按位置硬查表。例：尚博勒（哨卫 0.6/决斗 0.4）
  首杀权重 = 0.6×0.6 + 0.4×2.0 = 1.16；击杀权重 = 0.6×0.96 + 0.4×1.08 ≈ 1.01
```

**赛制**：先到 13 领先 2，12 回合换边，D25 起交替攻防的无限加时；BO1/BO3/BO5，决赛 BO5。

### 6.4 轮换与替补生态（v1.7 新增：让"坐板凳"成为可以经营的角色）

**问题**：旧规则下承诺未首发即积累不满、谈判降档惩罚极重——没人接受替补，轮换必然炸更衣室，7 人名单形同虚设。重构为四件事：

**① 出场期望模型（不满的真正来源）**

- 每名选手按承诺角色有出场期望份额：核心 ≥90%、首发 ≥70%、轮换 ≥35%、替补 ≥10%（28 天滑动窗口结算，训练赛出场折半计入；替补席坐满全场计 0.5 场份额）
- 每周结算**期望缺口**：实际份额低于期望才产生不满（每 10% 缺口 → 不满 +4/周，补足即停）；超出期望 → 忠诚 +
- **轮换一场不会炸**：不满只来自长期压榨，不来自单场轮换

**② 轮换协议（赛前沟通）**

- 阵容页可为单场勾选"轮换沟通"（免费，每周限 2 次，防止无限喂饼），向被轮换选手说明理由
- 成功率 = clamp(0.35 + 信任/50 + 正当理由（疲劳>70、伤病初愈、对手实力低 8+ 分、杯赛场）+ 更衣室技能 ×0.004, 0.15, 0.95)
- 成功：该场不减士气，信任 +2（"教练尊重我"）；失败：缺口惩罚减半——**沟通失败也比不沟通强**
- 提前沟通过的轮换在选手个人页可见（"教练说过我会轮休"），信息透明是信任的地基

**③ 替补的三条正路**

|---|---|---|

### 9.2 行动力（节奏阀门，继承并简化）

- 赛季中 **3 点/天**（原作 2 点：本作事件更多，放宽 1 点）；空档期 4 点/周
- 消耗：报价/问价/约战/商务/谈话/挂牌/解约 = 1 点；首发/战术/训练 = 0
- 点数用完仍可推进时间（原作同款），但收件箱会标注"今日还有免费操作未做"

### 9.3 事件卡系统（活世界的载体）

- 每次推进产出 0-3 张事件卡，来源：世界模拟器（AI 转会/宿敌/舆论）×日程（生日/合同/版本）×随机池（白噪声叙事）
- 卡片 = 叙事文本 + 2-4 个选项 + 后果（即时/延迟），例：
  > 【矛盾】Midnight 在采访中暗示指挥权归属不清。
  > ▸ 公开支持 Midnight（IGL 信任+8，Midnight 士气+5，其他选手不满+2）
  > ▸ 内部约谈（谈判检定：成功全员满意 / 失败矛盾+10）
  > ▸ 不回应（舆论 -5%，粉丝情绪下滑）
- **生日事件**（v1.9 补全，继承原作数值）：选手生日开 7 天窗口三选一——送祝福（士气 +2）· 送小礼物 $200 个人钱包（士气 +5、信任 +3）· 组织庆祝 $2500 俱乐部（全队士气 +2、羁绊 +2）；过期作废
- **抑制器**：同一选手 14 天内不出第二张负面卡；空回合补偿注入（§2 节奏原则）

### 9.4 分享与记忆产物

- **赛季海报**：年度结算自动生成（冠军照/战绩/金句/赛季最佳五杀截图），PNG 导出
- **回放链接**：MatchRecord + seed 可导出为 URL 参数（≤8KB 场次），他人点开即看同一比赛的播放器——"你看这场 1v4"成为玩家社交货币
- **名人堂页**：生涯冠军墙、门下弟子榜（带成长曲线）、下课/退休结局卡

### 9.5 经理人生涯（继承原作骨架 + 叙事强化）

- 捏人：年龄滑杆（成长曲线）× 随机 3 选 1 出身（2 强 1 弱 + 起始声望）× 8 点天赋 8 技能（训练/谈判/战术/眼光/体能/商务/更衣室/带新人）
- **董事会**：赛段目标（按实力分位下达）→ 信任 ±（达标 +6~16 / 未达 −2~18）→ ≤20 警告 → 警告后连败或 ≤6 **下课**（含下课结算页：任期、胜率、荣誉、下家评价）
- **跳槽**：主动申请（成功率 = 0.1 + 声望差×0.011 + 荣誉×0.03 + 战绩差队加成，谈判放大）× 被挖角 × 续约议价；**门下弟子加成**：你培养过的选手在公开场合的背书提升求职成功率（本作新增叙事闭环）
- **教练心态与个人经济**（v1.1 扩展：让工资有用）：单一条"教练心态" −2/周自然衰减，胜负 ±10；影响谈话成功率 ±5% 与建议语气彩蛋。个人钱包三类去处：
  1. **心态维护**：吃饭/娱乐（即时小回复）；假期（仅休赛期可用，心态大幅回升并清除一段时间的负面事件权重）
  2. **自我进修**：购买教练课推进技能经验（每赛季上限 4 点，技能上限仍 90）——用钱换成长，但占用休赛期行动力，形成取舍
  3. **生活事件**：部分事件卡选项需要个人付费（帮选手垫付搬家费、慈善捐款→声望）；个人财富计入退休结算与名人堂展示（"存款 $2.1M 的传奇教头"）
- **五年之约**：第 5 赛季末选择收官（结算结局）或继续；第 10 年强制退休进名人堂
- **难度**：普通 / 困难（AI 侦察你 + 预算微调）/ 职业（AI 会针对你的历史 BP 习惯）；开档只能上调

### 9.6 推进停靠规则（v1.1 新增：快进不再一路狂奔）

"推进到下一场比赛"按停靠点表运行，默认停靠密度"标准"：

| 停靠点 | 行为 |
|---|---|
| 我的正式比赛 | 停车进赛前流程（不变） |
| **每周训练结算**（每 7 天） | 停车：训练周报 + 下周课表确认（用模板 2 秒通过；不确认则按上周期延续） |
| 转会窗开启/关闭日 | 停车 + 补强进度待办 |
| 版本发布日 / 赛段切换 | 停车 + 公告 / 新赛段目标 |
| 红色事件卡（矛盾/伤病/报价与谈判到期） | 立即停车（设置里可降级为"继续推进，事后处理"） |
| 空档周未安排训练赛 | 停车提示一次（可勾选"本周跳过并不再提示"） |

- 训练赛在推进途中自动打完（保留原作设定），结果计入当段报告
- 设置提供停靠密度：最小（只停比赛）/ 标准（默认）/ 详尽（所有事件卡都停）

## 11. 技术架构

### 11.1 总体

```
┌─ 渲染层 React + TS + Zustand（页面/弹窗/表格）
├─ 播放器 Canvas 2D（独立模块，只吃 MatchRecord）
├─ 模拟核心 pure-ts/core（零 DOM 依赖）
│    ├ worldgen 种子生成器
│    ├ sim 日推进/训练/转会 AI/经济
│    └ match 引擎（事件流输出，确定性 RNG：xoshiro128** + 显式 seed）
└─ Worker 边界：日推进与整场比赛模拟都在 Web Worker；
    主线程只做 UI 状态同步与播放
```

### 11.2 关键决策

| 决策 | 理由（对应调研问题） |
|---|---|
| 模拟纯函数化 + 显式 RNG 流 | 确定性 = 回放/分享/PvP/调试的地基；原作边算边渲染是崩溃根因 |
| 同步存档到 IndexedDB（localStorage 只留元数据） | 原作 5MB localStorage 限制导致存档裁剪逻辑复杂；IndexedDB 配额宽裕 |
| MatchRecord 分级持久化（§5.3） | 控制存档体积的正规做法 |
| 代码分层 `core / app / data`，core 可跑 Node | 支持服务端赛季演算（异步 PvP）与 CLI 回归测试 |
| i18n 从第一天走 key-value | 文案是核心资产，但结构上不硬编码中文 |

### 11.3 性能预算

| 操作 | 预算 |
|---|---|
| 推进 1 天（世界演算） | < 50ms（Worker 内） |
| 单图模拟（24 回合） | < 30ms |
| 播放器渲染 | 60fps（每帧只画 ≤10 棋子 + 特效） |
| 存档体积 | 常规 < 4MB，硬上限 12MB 触发归档 |

### 11.4 存档

- `ACESAVE` 格式 v1：`{ meta, world, diff }`，版本迁移器（migrations[]）必配——原作 `Nc()` 补丁函数式的迁移证明是刚需
- 3 手动槽 + 自动档 + 每日轮换备份；导出/导入 JSON 文件永远可用（信任玩家）

### 11.5 未来多人钩子（v1 只做设计预留）

- 异步联赛：每周各玩家提交阵容/战术快照 → 服务端用同一 core 确定性演算 → 生成 MatchRecord 下发
- 世界 ID 分配、seed 派发、反作弊（快照校验）在 core 接口预留，不实现
