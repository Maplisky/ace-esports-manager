# ACE 教练 — core v0.1 + app v0.1

电竞战队经营模拟（GDD：`../design/ACE-电竞经理-游戏设计文档.md` v1.9）。
`src/core`：确定性模拟核心，纯 TS、零依赖、可在 Node/Worker/服务端三处运行（GDD §11）。
`src/app`：React + Zustand 界面，模拟在 Web Worker，存档在 IndexedDB。

## 运行

```bash
npm install        # 首次
npm run dev        # http://localhost:5173
node --test        # 13 个核心测试（无需依赖）
```

## 真实数据口径（v0.7）

- 数据源：vlr.gg（tools/crawl-vlr.mjs 爬取快照，tools/gen-real-ts.mjs 转 TS 模块；重爬：`node tools/crawl-vlr.mjs && node tools/gen-real-ts.mjs`）
- 选手：ign/真名/国籍/头像/逐英雄统计（?timespan=all）；八维属性由 rounds 加权指标线性推导（区间经校准使 VCT 队均值 ≈74）；主英雄职责 = 使用轮次最高英雄的职责；IGL 以队长星标近似（85% 概率），每队保证恰 1 名
- 年龄：vlr 无生日数据，按 vlrId 哈希确定性合成 19-29（口径已知）
- 青训/自由人：无 vlr 数据的缺员与市场池虚拟生成，Player.synthetic 标注（UI 角标「青训/虚构」）
- 地图：真实竞技图池 10 张（几何标签按地图结构手工标定）；英雄 = 游戏 28 英雄（id 与 vlr 英雄名直接对齐）
- 引擎对称性：BP 先手与每图先攻均为掷硬币（v0.7 检错：固定 teamA 先 pick 存在顺序统计量偏置）

## 验收状态（GDD §12 基准）

| 基准 | 结果 | 状态 |
|---|---|---|
| T1：87 分队 vs 72 分队 BO3 胜率 68-78% | **0.779**（1000 场） | ✅ |
| T2：同分队 BO3 胜率 47-53% | 通过（600 场） | ✅ |
| T3：进攻方回合胜率 46-56%（防守 +1.5 下） | 通过（300 场） | ✅ |
| 确定性：同 seed + 同状态 → MatchRecord 逐字节一致 | 通过 | ✅ |

关键调参常数集中在 `src/core/sim/strength.ts` 顶部（`ROUND_BASE_SCALE=0.28` / `DEF_BONUS=1.5` / `LOGISTIC_K=30` / `SWING_SD=6`）。

**重要教训（已写入测试注释）**：基准测试必须在每场前重置 form/morale/fatigue（或跑周恢复），否则"赢→状态涨→更强"的正反馈棘轮会把 50/50 滚成 84%。引擎本身无偏，是基准方法学问题。

## app 已实现

- 开局：世界种子 + 64 队选队（真实队伍与头像，按赛区分组展示；同种子世界一致）
- 总览：顶栏（日期/阶段/资金/行动力/董事会/下一场）、收件箱建议、推进一天/推进到下一场、首发速览、赛区积分榜（VCT-P/挑战者 × 霞/曜）、新闻流
- 赛程：我的比赛列表 + 比分 + 回放入口
- 阵容：首发/替补查看与轮换（7 人名单）
- 战术：每图多预案（快照保存/套用/首选标记）、英雄下拉带熟练度
- 训练：**团队课表与个人训练并行**（GDD §6.3 v1.1）——团队 7 天槽（跑图/复盘/对抗/休息，跑图涨图池熟练）+ 每人独立项目（枪法/反应/意识/道具/残局/协同/沟通/指挥/休息），展示具体训练指标、经验进度（100 经验 = +1 属性）与周预期收益，按职责/指挥推荐
- 赛前准备：每场我的比赛前弹出三步界面——①阵容确认（换替补）→ ②BP（自动推荐 + 手动改图，所见即所得）→ ③每图英雄确认（可套用预案），支持「进入观战」/「快进到结果」两路
- 比赛播放器 v2：记分牌（系列/地图/回合三层比分）、逐回合击杀流（带英雄名/首杀标签）、经济条（长枪/强起/eco）、自动导播（关键回合自动降速）、倍速、跳到结果；**真实地图俯视底图**（valorant-api 官方渲染；站点锚定官方包点位置，出生/中路/通道**逐图手工校准**——`map-overrides.json` + `node apply-overrides.mjs`，`/maps-preview.html` 可预览全部标定与布置位）；**开局战术驱动站位**（引擎按经济/指挥意识确定性产出 快攻/中路夹击/重心堆积/前顶压制 等，棋子按战术布置 → 首杀压进 → 下包收拢，CSS transform 平滑移动）；**对局实时战绩板**（四列：K/D/★FK、助攻、实时 ACS——伤害÷已完成回合×1.45，与赛后同式收敛，阵亡灰显）；终局 **比赛总结页**（窗口可滚动）——选手头像+按队伍分组（胜方在前），页签切单图数据（含特工头像），列＝KDA/ACS/FK·FD/残局，总 MVP 只从胜方产生、败方最佳标 SMVP，+ 强度归因条
- 存档：IndexedDB 自动存档，重启浏览器可继续

## 设计约定（务必遵守）

1. `src/core` 零 DOM 依赖，只用 erasable TS 语法（Node 原生跑 `.ts`）
2. 禁止 `Math.random` 与 `Date.now` 进模拟路径——一切随机经 `Rng`
3. 新调参一律进 constants + `../design/…调参表`，不散落魔法数
4. 改引擎先跑 `node --test`，三条平衡基准失败即回滚
